二、研究 AI Coding 工具

研究：

* Claude Code
* Codex CLI
* Gemini CLI
* OpenCode
* Aider
* GitHub Copilot CLI

重点分析 AI Coding 工具与普通 Terminal 工作流有什么不同。

例如：

* AI Agent 经常运行几分钟甚至几十分钟
* 输出内容非常长
* 经常需要用户确认权限
* 经常执行 shell 命令
* 经常修改代码
* 经常等待用户输入
* 经常在多个项目之间切换
* 经常需要查看 Git Diff
* 经常查看 Agent 当前状态
* 经常同时运行多个 Agent
* Agent 可能需要长时间后台运行
* 用户希望离开电脑后还能知道 Agent 是否完成

根据这些特点重新设计 Terminal，而不是简单复制 Windows Terminal。

最重要的原则

不要做：

“一个 React 页面 + 黑色 textarea + cmd.exe”

这种 Demo。

我要做的是一个真正能够长期使用的：

AI Coding Native Terminal

它应该让开发人员未来可以这样工作：

AI Terminal
│
├── Project A
│   ├── Claude Code
│   ├── Codex
│   └── Dev Server
│
├── Project B
│   ├── Claude Code
│   └── Tests
│
└── Production
    └── SSH

打开一个软件，就可以管理：

Shell
+
Project
+
Workspace
+
AI Agent
+
Remote Server

最终体验应该是：

Windows Terminal 的可靠性

* Warp 的现代交互
* VS Code 的 Workspace 思路
* tmux 的 Pane 能力
* Raycast 的操作效率
* 专门针对 Claude Code / Codex 等 Coding Agent 的任务管理能力。

先做充分研究和架构设计，再开始实现。

任何重要技术决策都需要说明：

为什么这么选、有哪些替代方案、代价是什么。

目标不是快速做出一个 Demo，而是建立一个真正可以持续迭代、长期使用、未来可以开源的 Windows AI Coding Terminal。
